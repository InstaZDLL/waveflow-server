### Issue #164, closed rather than fixed

The review asked that `the_sweep_collects_orphans_and_leaves_everything_else_alone`
stop launching `ffmpeg` from `PATH`. **The acceptance criterion could not be
met**, and checking that took reading `place_canvas`: it stages the bytes and
calls `probe_canvas`, which spawns a subprocess by design — its own comment says
so. Swapping `canvas_bytes` for a committed fixture removes no binary. The only
way to satisfy the criterion is to stop calling `place_canvas` and fabricate the
row by hand, which would leave the test asserting against a state it built
itself.

Three more facts settled it. The suite depends on FFmpeg **by decision** —
`CLAUDE.md` says so, `ci-rust.yml:64` installs it on both platforms saying
"every integration test needs them present", and `generate_audio_fixture` does
exactly the same thing for every scanner and media test. `canvas_bytes` has 16
call sites and `place_canvas` 27, so treating one test would leave fifteen
identical ones beside it. And the guideline the review cited — *hermetic, no
PostgreSQL or Better Auth* — is about service containers; the test uses a
temporary SQLite database and requires neither, so it already complies with the
rule invoked against it.

The reasoning is on the issue rather than here, because the review will raise it
again on the next pull request touching `tests/canvas.rs`.

## Traps

**A commit that is not pushed does not exist.** `11598d2` was reported as done
and was nowhere. Everything in it had to be re-established from the code. When a
change goes straight to `main` there is no pull request to merge later, so
leaving it local leaves nothing at all.

**A number in a handoff manufactures the next drift.** Three of the four
corrections above were numbers that were right when written: a commit hash, an
alert number, two counts of a test fixture. What is stable is the *pattern* —
the fixture, the rule that fires on it, the ruleset that refuses the branch. Give
the command that answers the number, not the number, and date the snapshot when
one is unavoidable.

**A review finding can cite a real rule and still be misapplied.** #164 quoted an
actual coding guideline at a test that already complies with it, and asked for an
acceptance criterion the code under test makes unreachable. Read the production
path before agreeing that a test is at fault — `place_canvas` spawning `ffprobe`
is what decided this one, and it is four lines into the function.

**`webapp/dist/` is gitignored and goes stale in silence.** The local build was
from 15 August while `webapp/src` last moved on 18 August, so `cargo run` was
serving an interface two commits behind its own source. CI always builds fresh,
so nothing catches this locally. Rebuild before judging the client:
`bun --cwd=webapp install && bun run build`, in that order, then `cargo`.

**Describe a competitor from its documentation, not from memory.** Navidrome's
feature list in the gap analysis is fetched and quoted. Two of the five absences
were then confirmed in this codebase rather than assumed — `getInternetRadioStations`
answers an empty container, and `jukeboxRole` is declared `false`.
