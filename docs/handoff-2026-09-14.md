### Why the correction shipped on its own

`retry_uncertain_scrobble` asked "has this entry already spent its joker" by
looking for another row naming it through `retry_of`. That holds only while
rows are immortal, and the retention this same session added makes them mortal:
a retry ends `sent`, so it is the first thing a purge takes, and the original
turns answerable again.

Measured rather than feared. With the retry row gone the entry reappeared in
`uncertain_scrobbles`, both gestures accepted it a second time, and the link's
`uncertain` counter put it back to `degraded` for a listen answered weeks ago —
decision 12's visible fault turned into a permanent false alarm.

decision rather than from the file.

### Three places that had to move together

Named instances are one change in three places, and two out of three would have
been worse than none:

- the unique index on `scrobble_link(user_id, provider)` forbade the case
  outright;
- the adapter registry held one target per recipient, so two instances would
  have shared whichever URL was registered last;
- `unlink_scrobble_on` withdrew "the live link at this recipient" before every
  new authorisation — so linking `maloja/bob` would have withdrawn
  `maloja/alice` and cancelled her queue.

Correcting the first two would have given a server that accepts two instances
and erases one, quietly, with somebody's listens turning `cancelled` as the only
trace.

### A name is not an identity

Removing an instance from the configuration breaks its links. So does pointing
the same name at another machine — the same substitution by the side door, and
the easiest to commit since it looks like fixing a typo. A link keeps a
fingerprint of the canonical URL, and reconciliation compares against it.

That canonicalisation is **its own, deliberately not `normalize_public_url`**.
That one answers an origin and throws the path away, which is right for shares;
a destination is not an origin, and `https://host/tenant-a` and
`https://host/tenant-b` are two of them. Reducing them to their origin would
have given them one fingerprint, and the guard would have waved through exactly
the move it exists to catch.

Catch-up and reconciliation run in `initialize`, under the writer gate, **before
the drain starts** — reconciling while the background task already runs leaves a
window, short and sufficient, in which listens leave for yesterday's machine.

The catch-up asserts and cannot verify: nothing in the database says which URL
was configured yesterday. Where the answer is ambiguous — legacy links and
several instances already declared for that recipient — **the server refuses to
start** rather than send a queue to the wrong profile. The way out needs no new
machinery: boot once with a single instance declared, then add the others. A
fresh install has nothing to catch up and declares as many as it likes on the
first boot.

**Deployment order, said rather than left to be discovered:** update first,
change a URL after. The other way round has the catch-up ratify the change,
because the guard compares against what was written and nothing was.

### What the Last.fm journey settles

Two routes and a table that lives twelve minutes.

`POST …/lastfm/authorize/{destination}` opens a state and answers where to send
the person; `GET …/lastfm/callback/{state}` takes the request token back,
exchanges it and creates the link.

- **The literal comes before the parameter.** Written
  `…/lastfm/{destination}/authorize`, a destination named `callback` would
  produce a path the return route claims just as well.
- **The random travels in the path.** Last.fm documents appending `/?token=…`
  to the callback and says nothing about one that already carries a `?`.
- **Both slash spellings answer.** What the browser asks for is
  `…/callback/{state}/`; axum normalises neither, so a route declared without
  the slash would fail at the journey's last step, for everybody, over one
  character.
- **The state is paired to a cookie**, `SameSite=Lax` and scoped to the return
  path. The session cookies are all `SameSite=Strict`, which is right for them
  and carries nothing at all on a return from another site.
- **The state is spent on the way in**, so a failure further on leaves nothing
  replayable.

The token is worth an hour and worth a profile: the callback path joins the
redaction prefixes, the answer carries `no-store` and `no-referrer`, and it
redirects at once to an address without it. `auth.getSession`'s response is the
one body this server reads from a destination — the session key is the point of
the call — and the one it must never log.

Last.fm stays unavailable without an operator's application **and** an `https`
`WAVEFLOW_PUBLIC_URL`. `GET /api/v2/scrobble-destinations` says which of the two
is missing, rather than letting a link fail later with no explanation.

### The decision this session reversed

Three commits in, this branch said an adapter never reads a response body, on
the strength of decision 12 — what this server publishes is a state, never an
echo. A review pushed back, and the argument was better: **decision 12 governs
what reaches a member.** It says nothing about what an adapter may read to reach
a verdict, and a number read to choose among five words is published to nobody.

What the earlier reading cost was a silent gap. Last.fm answers `200` carrying
`"error": 9` when a session key stops working, so a link whose credential had
died would have recorded every later listen as `sent` while nothing was recorded
anywhere. Maloja announces its refusals the same way, inside a `200`.

Both read now, and narrowly: an enumerated code, two counts, one word. Nothing
textual — `ignoredMessage` and Maloja's error object quote the submission back.
A body that will not parse leaves the status line deciding, and **the body only
ever refines a success**: a failing status already says everything it could, and
letting the body answer for a `429` returned the adapter's own zero wait instead
of the `Retry-After` the header gave.

## Traps

**An inversion whose anchor spans two lines silently does nothing.** A
`grep -qF` guard with an embedded newline matches as *several patterns*, so the
guard passed while the substitution found nothing, and the test ran green
against an unmodified tree — a "proof" with no defect reintroduced. Single-line
anchors, or line numbers; and compare the file's digest before and after, which
is what caught it here.

**A refusal can be reached by an earlier layer than the one under test.** A case
named "someone else's browser" sent *no* cookie, which the route refuses before
the service is called — so deleting the cookie comparison in the service left
the test green. The case has to carry a well-formed cookie this server never
issued. Where one status can come from two layers, feed it something that
crosses the first to land on the second.

**`all` over an empty collection is true.** "Every link is alice's" was
satisfied by a server that had linked nothing, which was the one outcome that
assertion existed to exclude. Count, then name.

**Splitting on the first `=` is not safe on a URL.** The destination parser read
`https://wf:pa=ss@host` as the name `https://wf:pa`, and the name is what a
refusal quotes back — scheme, account and half a password in a startup error,
from the one paragraph that promises the opposite. `=` is an ordinary character
in a generated password.

**`endpoint` drops a trailing slash, and one destination needs it.** Last.fm
documents `/2.0/` and answers `/2.0` with a redirect that `outbound_client`
follows none of. Every call would have failed, read as the destination having
moved. The integration test found it; no reading of the adapter had.

**A count taken from a decision is not a count taken from the file.** The RFC
said three readers laid on the join; there were four. The same shape as the
2026-09-12 handoff's note about claims checked against callers.
