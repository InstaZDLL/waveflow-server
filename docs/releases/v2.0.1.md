# WaveFlow Server 2.0.1

A small release after 2.0.0: a ready-made way to put the server behind HTTPS, and one boot warning fewer.

## New

- **HTTPS with Caddy, ready to copy.** [`packaging/caddy/`](https://github.com/InstaZDLL/waveflow-server/tree/v2.0.1/packaging/caddy) holds a compose file and a Caddyfile that run the server behind Caddy. Set the name your clients will use in a `.env` and run `docker compose up -d`. A public name gets a certificate from Let's Encrypt, or from ZeroSSL when Let's Encrypt cannot issue one. A name ending in `.internal` or `.home.arpa`, or an IP address, gets one from Caddy's own local authority. The server publishes no port of its own, and the proxy is already trusted, so sign-in protection counts each client by its own address.

  The [operations guide](https://github.com/InstaZDLL/waveflow-server/blob/v2.0.1/docs/guides/operations.md#the-recommended-setup-caddy-in-the-same-compose-file) explains how to make your devices trust the local authority, why an untrusted certificate stops offline listening in the browser and Android apps, how to move a server you already run onto this setup without losing its data, and what to write for nginx instead.

## Fixed

- **A server that never asked for Last.fm no longer warns about it at every boot.** The warning now appears only when you named a Last.fm instance yourself, with `WAVEFLOW_SCROBBLE_LASTFM_URL`.

## Install

```bash
docker run -d --name waveflow \
  -p 4533:4533 \
  -v waveflow-data:/data \
  -v /path/to/music:/music:ro \
  ghcr.io/instazdll/waveflow-server:2.0.1
```

The image runs on `linux/amd64` and `linux/arm64`, and is the same, digest for digest, on Docker Hub as `instazdll/waveflow-server:2.0.1`. `latest` now follows this release.

## Upgrading from 2.0.0

Pull `2.0.1` and start it on the same data volume. The database schema has not changed, so there is nothing to migrate, and `2.0.0` still opens the same volume should you need to go back.

To move onto the Caddy setup, stop the server you run now before starting the new one, and point the new compose file at your existing volume with `WAVEFLOW_DATA_VOLUME`: the guide's "Moving an existing server" walks through it. Started without that line, it begins on a new, empty volume.
