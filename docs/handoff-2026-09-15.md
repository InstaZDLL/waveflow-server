### The journey was broken at its last step

`lastfm_callback` finishes an authorisation and redirects to
`/settings/scrobbling`. **No such route existed.** Somebody who went all the
way to Last.fm and back landed on the not-found page with their link made and
nothing saying so. The path is therefore the server's and not a preference,
and the screen sits exactly there.

### What the screen decides

- **Instances are named, addresses never are.** A member picks among the names
  this server publishes. Two instances of one recipient are ordinary on a
  household server, and each carries its own row, its own field, its own link.
- **An instance that cannot be linked says why**, rather than offering a
  control that would fail.
- **A link to an instance the operator has withdrawn stays on screen.** The
  server breaks such a link instead of erasing it, because the queue behind it
  is somebody's. A listing built from the offered instances alone would drop
  the row, and with it both the explanation and the way to withdraw the
  authorisation.
- **Ambiguous listens are named, not just timestamped.** An entry carries no
  title — decision 12 keeps the envelope out of the API — and `played_at` is
  documented as the handle a client matches against its own history. Two plays
  at one instant match nothing: guessing would put the question about the
  wrong listen. The naming is capped at fifty tracks; **the listing never is**,
  because each entry is a decision that is owed.

### Two server changes the screen required

**An ambiguous listen names its instance.** `UncertainScrobble` carried the
recipient alone, so somebody with two Maloja instances was asked to decide the
fate of a listen without being told which of them may already hold it.

**A broken legacy link is still a pair.** Reconciliation broke a link whose
recipient declares no instance and named it nothing, so the API published an
empty instance — and nothing could remove it, because `unlink_scrobble_on`
matches `destination=?` and no comparison is ever true of NULL. It is named
`default` before it is broken: not a guess, but the name a link made under
#191–#193 had, when its recipient declared one instance and nobody had to name
it.

### Search takes a library, and the reason it did not was wrong

`/api/v2/search` was the last catalogue route the active library did not reach,
and the screen said so rather than pretending. The cost had been overstated for
a year: scoping was said to mean rewriting three FTS queries in a service the
frozen Subsonic façade shares. `search` has exactly one caller, and
`search2`/`search3` reach `catalog_search` — a separate path with its own three
queries that **has honoured `musicFolderId` all along**. The native surface was
behind the façade, not ahead of it, and the frozen contract is untouched.

### RFC-008 has no open question left

Decided 2026-09-15 after external review, as **decision 9**: the same content in
two libraries is two files and two quota charges. The negotiation stays bounded
to the target library, and knowing the bytes exist elsewhere changes neither the
verdict, the transfer, the validation, nor what is counted.

[RFC-009](rfcs/RFC-009-track-canvas.md) shares canvas blobs and looked like the
way. It is not transposable, and the reason is nameable: the canvas has a
**global store**, `canvas_dir`, while decision 5 puts an audio file inside its
own library's tree so the ordinary scan finds it. **The file's location is its
belonging.** What carries over from RFC-009's decision 11 is only its privacy
half, which decision 2 already stated here.

A door is left open with three locks: transparent physical deduplication may
come later — a reflink where the filesystem allows one — only if it creates no
cross-library oracle, no dependency between two libraries' files, and no change
to the API contract. Anything observable from an API is a decision, not an
optimisation.

## Traps

**`vite preview` serves `dist/` and does not build.** The Playwright
`webServer` runs it, so a local `bun run test:e2e` after editing `webapp/src/`
exercises whatever was last built — green on code just changed, or red on a fix
already written. It cost a false red here, and it is the web form of the stale
artefact trap: no timestamp betrays it, and `vite build` takes 250ms and says
nothing about what it replaced. **Build before every `test:e2e`, and inside any
inversion script that touches `webapp/src/` — both when mutating and when
restoring.** CI does not fall into it; it builds first.

**An inversion that is too wide takes an earlier assertion down with it.** The
three search guards were first inverted to `? IS NOT NULL`, which also broke
the *unscoped* path, so all three fell on an assertion about searching every
library and said nothing about narrowing. The guard-only mutation —
`(? IS NULL OR ? IS NOT NULL)`, always true, both binds still consumed —
is what separated them.

**A mock that collapses a distinction cannot fail a client that collapses it
too.** The end-to-end scrobbling mock held every link as `maloja` and matched an
unlink on the instance name alone. `default` is the name all three recipients
use, so withdrawing one would have withdrawn its namesake — the exact fault the
unique index on `(user_id, provider, destination)` was rebuilt to prevent,
reproduced inside the harness built to catch it.

**A recorded value that is written in rather than read cannot disagree.** The
same mock pushed the verb it expected instead of `route.request().method()`,
on all three branches that record a write, so three assertions agreed with
themselves whatever the client had sent.

**A doc comment that states an intention is not an assertion.** The test for a
legacy link with nothing declared said "leaving the two columns empty would hand
the next reconciliation a row it could not read" and checked none of it — the
third time this repository has produced that shape. Likewise
`UncertainScrobble::last_failure` advertised `stalled` and `auth_broken` and
wrote neither.

**A count taken from a handoff is not a count taken from the file.** Two of the
previous handoff's four "small" items were already closed when it listed them,
one of them by a commit on `main` three days earlier. Reading the file is what
showed it, and it took one grep.
