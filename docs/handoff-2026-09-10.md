### The plan was wrong six times, and only building found it

The gap analysis was written in read-only mode. Every one of these was recorded
in it as a correction, dated, rather than quietly amended:

1. **Page headers existed** since `e7c8b64`, on eight pages. What was missing
   were the controls in them.
2. **Cover hover existed** — `.grid a:hover .cover`. What was missing were the
   actions.
3. **The login screen's language was never a defect.** `I18nProvider` reads
   `navigator.language` and wraps `RouterProvider`.
4. **The serif was never orphaned.** It carries `h1, h2, h3` — every page title
   — the brand, the missing-cover letter and the 404. It was declared four
   times in two spellings, which is what made it read as an accident.
5. **Three of the "eleven wirings, not one line of server" needed server work.**
   Tag correction (below), library members (no route listed them), and the scan
   stream (below).
6. **The tag-correction contract was wrong for two of its nine fields.**

The last one is the one to carry forward. `source = override ?? file` holds for
the seven scalar columns, because the projection merges them with `COALESCE`.
It does **not** hold for artists and genres: correcting either is *materialised*
— `apply_track_override_lists` deletes from `track_participant` and reinserts,
and overwrites `artist_display` — because those rows feed every projection and
the search index. **Once a correction exists, the file's own credits are no
longer in the database**, only in the file. An editor can therefore show
provenance for seven fields and must offer to restore the other two without
previewing what they will become.

### Two things the API could not do that it looked like it could

**The scan progress stream is not readable by `EventSource`.** The route
authenticates on a bearer token — `authenticated()` reads the `Authorization`
header — and `EventSource` sends no headers at all. That is the same wall
`<audio src>` hits and stream tickets exist to get around. The way through is
`fetch`, whose body reads as it arrives, which puts frame splitting on the
client: `drainEventStream` is a pure function with its own tests, because a read
never lands on a frame boundary.

**A library's members could be written and never read.** `PUT` and `DELETE` on
`/libraries/{id}/members/{user}` have existed since M4 with nothing to list
them, so an interface could grant and revoke without showing who already had
access. `GET /api/v2/libraries/{library_id}/members` closes it.

### Decisions taken, and where they are written

Recorded in the plan's open section, each dated 2026-09-07:

- **One active library at a time.** The web UI works inside one library;
  changing it changes the catalogue's scope and never merges catalogues.
  Aggregation would have to answer what a record held by two libraries is, which
  is the identity problem `src/pid.rs` settles for files, asked again a layer up.
- **Effective value everywhere, provenance only in the editor.**
- **Nothing on i18n now**; a third locale converts the dictionaries to
  dynamically loaded modules.
- **CodeQL keeps analysing `tests/**`.** The narrow suppression is not
  expressible: the config does not intersect path and rule, so it is
  `paths-ignore` for every rule or a query filter for every path.

### 2. #177, once that audit is done

`PATCH /api/v2/tracks/{track_id}` replaces the whole override set: a field left
out is erased, and a client cannot avoid that because until this week it could
not read the corrections it would have to resend. The read half now exists as
`GET /tracks/{track_id}/overrides`. What is left is making the write a real
partial patch — absent leaves alone, a value sets, `null` removes.

**`Option<T>` cannot say three states.** `TrackMetadataPatch` declares
`pub title: Option<String>` under plain serde, where an absent field and a
`null` field both deserialise to `None`. It needs `Option<Option<T>>` with a
`deserialize_with`, or the contract gets written, "absent leaves alone" gets
tested, and `null` behaves identically without a test noticing.

## Traps

**A survey done from the screen sees what is absent from a screenshot, not what
is absent from the code.** Six of the plan's claims were wrong, and every one of
them was found by building the thing the claim described. Read the code before
believing a document about the code — including a document written three days
ago by someone who had just read that code.

**Choosing gates by which half you think you touched is how `main` goes red.**
Renaming `/api/v2/songs` was a server change in my head, so it was checked with
`cargo fmt`, `clippy`, 162 Rust tests, biome, `tsc` and the web build — and not
with `test:e2e`, the one gate that exercises the client against the paths it
calls. The Rust suite caught its own stale reference; nothing was watching the
browser's. `CI (Web)` failed on `main` for an hour. **A route rename touches the
end-to-end suite, whichever half it looks like.**

**`?? []` turns an ignorance into a fact.** Twice on one branch, a screen said
something true-sounding about a failed request: "no token on this account" and a
grant control offering access to people who already had it, printed under the
notice saying the list could not be read. An empty list and an unknown list are
different, and where an empty list is unreachable — every library has an owner —
the fallback can only ever be a lie.

**The inversion that proves a test can itself fail to happen.** Removing a fix
and watching the test fall is the rule; on 2026-09-10 it silently did nothing
three times, in three different ways:

- a `replace` that matched nothing, because the formatter had reflowed the line
  since — assert the anchor rather than trusting the silence;
- a removal that left a variable unused, so the build failed and the suite ran
  against the **previous bundle** — remove what becomes unused too, and check
  the build succeeded before reading the result;
- a fixture too small to tell the two behaviours apart: with one library, "list
  then panel" and "every list then every panel" render the same rows.

The question is not whether the test passes. It is whether it **could have
failed**. When an inversion produces no failure, suspect the inversion first.

**`pkill -f` kills the shell that ran it** when the pattern appears in its own
command line — seen here taking a `cargo test` down with it. Use
`ps -eo pid,args | grep "[v]ite preview" | awk '{print $1}' | xargs -r kill`.
And on this machine, `cargo test --all-features` unbridled is OOM-killed while
compiling fourteen test binaries: pass `-j 1 -- --test-threads=2`, and kill the
`vite preview` servers the screenshot scripts leave behind.
