### The shape of receiving a file

Two locks decide, and they answer different questions. `Owner | Manager` says
**who** — the pair that may already spend the owner's disk on a rescan.
`library.accepts_uploads`, false by default, says **where**; a server that was
merely upgraded must not have become a deposit. It is set through
`waveflow library set-uploads --accept`, audited: the operator's call, not a
member's.

Three surfaces: `POST /api/v2/libraries/{id}/uploads` negotiates a batch,
`PUT /api/v2/uploads/{id}/chunks/{n}` takes one fragment,
`POST /api/v2/uploads/{id}/commit` turns it into a track. The negotiation and
the fragment routes each carry **their own body ceiling**, derived from the
batch limit and the fragment size so the two cannot disagree. The router's
global 16 KiB stays where it is: an API whose every route accepts that much
cannot be drowned in a request body.

Four invariants are worth carrying forward, because most of the review rounds
were about them.

- **Nothing partial is ever visible.** Fragments land in the destination
  directory under `<uuid>.part`. Same directory means same filesystem, so the
  rename at commit is atomic rather than a copy with a window. Invisibility
  comes from a rule that already exists — `discover_audio` filters on extension
  and skips no directory, hidden or not (`src/scanner.rs`, `WalkDir` with no
  `filter_entry`).
- **File first, row second, always.** The row is the only thing that remembers
  a file exists. Only a genuine "not there" counts as success; anything else —
  a failed removal, an I/O error on the existence check — keeps both the row
  and the lock so the next sweep retries.
- **The final name is the hash, and it is not a session's property.** The unique
  index is `(library_id, user_id, declared_hash)`, so two members can hold
  sessions for the same hash in one library. The sweep reaches that name only
  under two guards: no track references the path, and no other session shares
  the hash.
- **Authorisation is re-decided every request.** A session is not something a
  client carries away. `src/stream_ticket.rs` already held this rule for
  playback; a transfer lasts far longer and costs far more. A member removed
  gets 404, a library closed mid-transfer gets 409.

### `scan_id` is optional, and `NULL` says something

`apply_catalog_track_in_transaction` takes `Option<Uuid>`, and `None` means
**this row did not come from a scan** — never "the scan is unknown". A fake
`scan_job` would have put a fact in the scan history that never happened, and
widening `scan_job.trigger`'s `CHECK` would mean rebuilding the table to declare
that an upload is a kind of scan.

That meaning only exists because `mark_unseen_unavailable` honours it. It used
to read `NULL` as never-seen, therefore gone — so a file received while a scan
was running would have been marked unavailable by that scan, whose walk began
before the file existed, and a deletion announced to every client seconds after
the arrival. It now sweeps an unstamped row only when it predates the scan.

## What the next agent should pick up

### 1. (d), the canvas asset — the last of the four desktop requests

The other three are done: (a) cacheable artwork with the `429` contract (#143),
(b) `PATCH /api/v2/tracks/{id}` (#146, #147), (c) receiving a file (#149, #151).

(d) wants a short RFC before code, because the decisions are real and it does
**not** simply reuse the upload machinery — that machinery is tied to a library
and produces a track, and a canvas is neither. What to settle:

- **Where the bytes live.** Not the library root: it is not audio, and the
  operator did not put it there. `artwork_dir` is the precedent — server-owned,
  content-addressed, outside the scanner's model.
- **How it is served.** `<video src>` cannot carry an `Authorization` header,
  which is the problem `src/stream_ticket.rs` already solved for audio. Its
  payload is the fixed 40-byte `(user, track, expiry)`, so a canvas needs either
  its own ticket shape or a discriminator.
- **Whether it survives a rescan.** It is user-supplied — nothing in a file
  produces it — so it belongs beside the track like `track_override`, never
  rewritten by a scan. Artwork is the opposite and is not the model to copy.
- **How it announces itself.** RFC-007 decision 5: no event for a
  content-addressed resource, because the bytes behind a hash never change. Only
  the *link* is a change, and it travels in the track's `upsert`.
- **Quota.** It is the operator's disk too, and the arguments from RFC-008
  decision 1 apply unchanged.

### 2. RFC-007's remaining open items

The origin device is closed by #152. Three left, none urgent:

- **Retention values** — age, or events kept per library. The watermark column
  (`library.events_purged_through`) exists and sits at 0; nothing purges yet, so
  the expiry answer is correct but never exercised.
- **Acknowledgement.** The user journal acknowledges by `(account, device)`; the
  equivalent here is `(device, library)`, and the table that carries it is
  undecided.
- **Whether `album` and `artist` events are needed** or derivable from `track`
  events by the client. The `CHECK` admits them already; nothing emits them.

## Traps

**Remove the fix and watch the test fall. Every time.** This caught two vacuous
tests this week, and both would have shipped.

- `nothing_half_written_is_ever_visible_to_a_scan` passed with the rule removed:
  a truncated file fails to parse whatever it is called, so the staging name
  decided nothing. It now stages a **complete, valid WAV** that is only part of
  what the transfer promised — the case the RFC actually describes.
- A test for the contested-session guard passed for the wrong reason: **a
  negotiation sweeps before it answers**, so opening the second session after
  expiring the first removed the file while nothing yet contested it. Both
  sessions must be open before either expires.

**The config is copied at startup.** `DomainServices` and `AppState` take their
values from `Config` in `initialize()`. Mutating a `Config` afterwards changes
nothing, and a test that tunes a limit after building the app silently exercises
the old value. Tune inside the closure that builds it.

**Backticks in a `git commit -m` body are shell substitution.** One pair around
`?` amputated a sentence and the commit still succeeded. Read the message back
with `git log -1 --format=%B` before pushing, or write it to a file and use
`-F`.

**Two adjacent `&str` parameters are a transposition waiting to happen.**
`record_library_event` had `entity_type` and `action` side by side; swapping
them would have compiled, passed, and written a vocabulary the `CHECK` accepts
by chance. They are a struct now, `LibraryChange`.

**Making a file undeletable also makes it unrenameable.** Replacing it with a
non-empty directory is the deterministic way to fail `remove_file` on Linux, and
it is what the sweep tests use — but it means the branch where a rename succeeds
and an unlink fails has no deterministic test. A self-referential symlink is the
way to fail an existence check while leaving a neighbouring file ordinary.

**Two things are not covered and are not claimed to be**: the timing window the
per-session sweep lock closes, and the branch where renaming a file back matters
because unlink failed. Both are stated in their commit messages rather than
implied to be tested.
