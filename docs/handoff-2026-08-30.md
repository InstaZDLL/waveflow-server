### The shape of a canvas

Four things are worth carrying forward, because the review rounds were about
them.

- **The store is server-owned and content-addressed.** `canvas_dir` beside
  `artwork_dir`, never the library root — that is the operator's collection, and
  an object the server produced has no business changing what "delete the
  library" means. Two tables: `canvas` describes a blob, `track_canvas` says
  which track points at it and is the only thing that makes a blob referenced.
- **The quota counts distinct blobs, never links.** An album's shared loop is
  billed once however many tracks name it. Charging links would make the price
  depend on how many tracks a canvas is attached to.
- **The lock is per hash, not the writer gate.** RFC-009 first asked for the
  gate to span the byte write and the unlink; `src/services/mod.rs` has said the
  opposite since RFC-008 — *file I/O has no business happening while the
  process-wide gate is held*. The RFC was amended rather than left to disagree
  with the code.
- **The kind is inside the sealed ticket.** Without it a canvas ticket opens the
  audio and the reverse: two resources three orders of magnitude apart in
  bandwidth, behind one authorisation the client never asked to widen. `0x01`
  audio, `0x02` canvas, `0x00` refused on purpose.

### 2. `artwork_dir` was not "the same shape, another store"

The entry below said so, and it is wrong in the way that matters. The columns are
three, as it said. The shape differs because of **who writes the files**.

The canvas store is written by this process, so a placement and a sweep take the
same per-hash lock. `waveflow_core::scanner::extract_cover` writes covers from a
blocking task in a crate that has never heard of `DomainServices`. There is no
lock to take, and the writer gate is not a substitute — `DomainServices`' own
field comments forbid file I/O under the process-wide gate. Age stands in for the
lock instead, as it already does for the canvas *working* files.

Three things the next reader should know rather than rediscover:

- `extract_cover` writes only `if !out_path.exists()`, so a re-reference
  refreshes no timestamp and **a window stays open**. It is tolerable only
  because a cover's bytes are in the audio file, which is read-only and still
  there: the store is reconstructible, unlike the canvas store. The module says
  this rather than claiming the window is shut.
- `artwork_dir` also holds `<hash>_1x.jpg` and `<hash>_2x.jpg`, which **nothing
  in the database names**. A classifier that knew only covers would leave two
  files per cover for the life of the instance.
- The `artwork` row deletion needs no grace period: `upsert_artwork` inserts the
  row and the column naming it in one transaction, so a committed row is already
  referenced.

### 3. The canvas sweep's lock is demonstrated now

The old entry called it reasoned rather than demonstrated. The obstacle was never
the ordering — it was **scope**. `canvas_lock` is private and every canvas test
is an integration test, so there was nothing to hold. A unit test inside the
module holds it, which is what a placement holds between its bytes and its row,
and the interleaving stops being raced for and starts being arranged. Removing
the lock now fails on the first assertion. First unit test under `src/services/`.

### 4. Smaller, still owed

- **A CodeQL alert on the test fixture, recurring.** Check which one is open
  before assuming anything, rather than reading a number off this line — see the
  command above. What is stable is the pattern: every new
  `security::hash_password("correct horse battery staple")` under `tests/`
  raises `rust/hard-coded-cryptographic-value`, and the ruleset refuses the
  branch until it is dismissed. Two ways out, neither taken: dismiss each alert
  as it appears, or stop the rule firing on code CodeQL itself classifies
  `test`. The second was offered and not chosen, so the first is the standing
  answer.
- A `Json<T>` route rejects a malformed body *before* `authenticated` runs, so an
  unauthenticated caller gets 422 rather than 401 there. Noticed while writing
  #168 — the 403 declaration, not a sweep, as an earlier version of this line
  had it — and deliberately not changed: the schema is public in `openapi.json`
  anyway, so the oracle tells nobody anything new. Re-examined on 2026-09-06 and
  the answer held. `authenticated` is called in each handler's body while
  `Json<T>` is an extractor in its signature, so axum runs the extractor first;
  making it 401 would mean either a layer configured per route with the `Access`
  the call already carries, or taking `Bytes` and parsing by hand in the
  nineteen handlers that authenticate — which drops the typed extractor that
  generates `openapi.json` in the first place. The case also needs a malformed
  body *and* no credential: an expired token on a well-formed request still gets
  its 401. The condition to watch is not this route but that document — if
  `/openapi.json` ever stops being served unauthenticated (`src/lib.rs`), the
  422 becomes the only oracle on body shapes and the trade changes.

## Traps

**A document's header is not evidence about the code.** Every RFC here says
`Statut : Proposed`, including the two that had been in production for days. The
desktop agent read it, concluded three RFCs were unimplemented, and held three
of its own batches as blocked on a server that was ready. It had even noticed
`src/api/uploads.rs` and said aloud that RFC-008 "may be partly implemented" —
then moved on. **A contradiction noticed and dropped costs more than one never
seen.** The fix was not to flip the statuses: a status word cannot be audited, a
pull request number can. Each RFC now names its PRs, and `CLAUDE.md` says the
routes in `src/lib.rs` and the dated files under `migrations-v2/` are the only
real account.

**Remove the fix and watch the test fall. Every time — and say so when it does
not.** Two this week did not, and both are written down rather than implied
covered:

- Removing the reference-count guard in the blob lifecycle changed nothing,
  because `track_canvas.canvas_hash` references `canvas(hash)` with no
  `ON DELETE` clause and SQLite refuses the delete while a link remains.
  Removing *both* fails. The two are belt and braces; the constraint is the one
  that currently speaks.
- Removing `-map_metadata -1` and `-fflags +bitexact` from the audio remux
  changed nothing either: one FFmpeg build muxing the same packets twice agrees
  with itself. What they defend against is the version string that differs
  between builds, which no test running against a single build can see.

**A test can pass for the wrong reason, and that is worse than no test** —
because it also stops anyone looking. The acknowledgement's tenancy case sent
the *owner's* device with a stranger's token, which is refused a step earlier by
the device check and says nothing about membership: deleting the membership join
did not fail it. The case that exercises the join is the stranger's own device
against a library they cannot see. Three guards, and only two fell until the
test was fixed.

**An aggregate with no `GROUP BY` returns one row when the `WHERE` matches
nothing.** A tenancy predicate written as `SELECT COALESCE(MAX(e.cursor), 0)
FROM library_member m JOIN …` compiled, passed everything, and enforced nothing:
no membership still answered `Some(0)`, and the branch beneath it was dead. The
subquery form returns no row. Caught by running the SQL against `sqlite3`, which
is the only thing that could have caught it — no test distinguishes the two.

**A clock read twice is not a boundary test.** The retention bound is exclusive,
so "exactly thirty days old" is one instant; a test that read `now` and let the
purge read it again put the boundary event on whichever side the intervening
milliseconds chose. It passed once and failed the next run for nothing that had
changed. `purge_library_events` takes `now_ms`, the way `sweep_expired_sessions`
already did. **It was caught because the suite was run again rather than once.**

**Correctness that leans on a bound enforced three files away stops being
correct when somebody edits the other file.** The acknowledgement's ceiling was
right only because `parse_positive_env` refuses a retention floor of zero. The
expression now stands on its own, and the test that reaches the branch builds a
configuration the server would refuse to start with — and says so, because a
guard no test can reach is a guard nobody can check.

**A comment that contradicts its function is worse than no comment.** The
probe's comment said an audio stream "is deliberately not inspected" for two
commits after the code began detecting and removing it. It survived because the
decision changed and the paragraph three lines above the change did not.

**`git checkout <path>` restores from the index, not from your intent.** Used to
drop a temporary debug print, it took the real assertion out with it — the
commit would have carried a message describing a fix that was not there. Read
the file back before committing, not just the diff you meant to make.

**A feature branch is not created by wanting one.** One commit landed on `main`
by forgetting `git checkout -b`. Nothing was pushed, so `git branch` then
`git reset --hard origin/main` fixed it — but the hard reset also discarded an
unrelated uncommitted change that had been sitting in the tree since before the
session.

**Startup validation constrains what a test can configure.** `validate_canvas`
refuses a per-canvas ceiling above the library quota, so a test cannot squeeze
the quota between the arriving size and the stored size to prove which one is
charged. Fill the room instead: a first canvas takes all but exactly the
remainder. And when the filler must be large, buy the bytes with *detail* rather
than *duration* — a flat colour compresses to about a kilobyte a second, and a
filler long enough to matter trips the duration ceiling first.

**Two adjacent knobs are not one knob.** `accepts_uploads` and `accepts_canvas`
answer different questions, and the RFC only found that out because it had
written down the condition under which its own answer would stop holding. A
decision that names what would falsify it is worth more than one that sounds
certain.

**An approval is not a mergeability check.** #167 was recorded here as "approved
and mergeable" and was neither — a ruleset held it on a CodeQL alert nobody had
looked at. `reviewDecision` and `mergeStateStatus` are different questions, and
only the second one is about whether the button works.

**A security scanner's false positive is still a blocked merge.** The alert on
`generate_token("test-password-")` is wrong on the facts, and being wrong changed
nothing about the ruleset. Deciding it is a false positive is the operator's
call, not the agent's, and dismissing one is not the same as fixing the nine
sites that will raise it again.

**"One line owed" is a claim about a defect's size, and defects do not report
their own size.** The 403 was recorded as a single omission on one route. Reading
every route's annotation against the access its handler asks for turned up
nineteen — and the audit that found them also found the one an audit of
*mutations* could never have found, because it was a `GET`.

**A test that reads the document a pass just wrote is not a test.** It confirms
the pass ran. Ask the running server instead and let the document be the thing on
trial; the test then finds routes nobody listed for it.

**A guard's scope, not its subject, is what usually makes it untestable.** The
canvas lock went undemonstrated because every test that wanted it was in another
crate. Nothing about the lock had to change — the test moved.

**Stale prose accumulates fastest right next to the change.** The canvas module
header still said "No sweep exists yet" three hundred lines above the sweep #163
added, and `CLAUDE.md` still counted thirteen test targets after `canvas` became
the fourteenth. Both were written by someone who edited the code and not the
paragraph describing it.

**A review finding can be right about the danger and wrong about the fix.** #169
was asked to join the handle `spawn_thumbnail_job` returns, before ageing the
files it writes. There is no handle — it returns `()` and lives in
`waveflow_core`. But the thread it detaches does write the two names the test
writes, and the test was passing because that job silently fails on these
fixtures. Probed at 0ms, 500ms and 2s: the store holds the cover alone. The fix
was not the one asked for; the concern was real, and reading the timestamps back
before the decisive sweep turns a future flake into a failure that names itself.

**A stand-in has to stand in for what the server actually does.** The unit test
committed its row straight to the pool while `link_canvas` takes the writer gate
around that same statement. Cosmetic in a test about values, not in one whose
subject is what two concurrent writers see. Checking there was nothing to
deadlock against — the sweep takes no gate, in any of the three functions
involved — was the part that had to come before the change, not after it.

**A rule can apply to one call site and not to the eight that look like it.**
`writer_guard` is `pub(crate)`, so the direct writes in `tests/` cannot take it;
theirs is forced, not chosen. The unit test can, which is the same reach that let
it hold the private lock. Before answering "why here and not there", find out
whether there had a choice.
