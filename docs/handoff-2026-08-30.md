### The shape of a canvas

Four things are worth carrying forward, because the review rounds were about
them.

- **The store is server-owned and content-addressed.** `canvas_dir` beside
  `artwork_dir`, never the library root — that is the operator's collection, and
  an object the server produced has no business changing what "delete the
  library" means. Two tables: `canvas` describes a blob, `track_canvas` says
  which track points at it and is the only thing that makes a blob referenced.
- **The quota counts distinct blobs, never links.** An album's shared loop is
  billed once however many tracks name it. Charging links would make the price
  depend on how many tracks a canvas is attached to.
- **The lock is per hash, not the writer gate.** RFC-009 first asked for the
  gate to span the byte write and the unlink; `src/services/mod.rs` has said the
  opposite since RFC-008 — *file I/O has no business happening while the
  process-wide gate is held*. The RFC was amended rather than left to disagree
  with the code.
- **The kind is inside the sealed ticket.** Without it a canvas ticket opens the
  audio and the reverse: two resources three orders of magnitude apart in
  bandwidth, behind one authorisation the client never asked to widen. `0x01`
  audio, `0x02` canvas, `0x00` refused on purpose.

### The desktop's note, and what it corrected

A note arrived from the desktop agent on 2026-08-30 with four arbitrations. Two
were already shipped and needed nothing. Two changed the code:

- **A door of its own** (#158). RFC-009 had reused `accepts_uploads` on a
  condition it stated out loud — the two answers go together *until somebody
  shows a case where they part*. The desktop showed one: a read-only
  installation is the most common configuration there is, and an operator may
  want a few hundred kilobytes of loop on a machine he refuses to let grow in
  audio.
- **The soundtrack** (#160). `CanvasStage.tsx` renders its `<video>` with a
  hard-coded `muted`, so no client can choose to hear a canvas. Keeping the
  stream meant storing bytes nobody will ever hear, taken out of the same 4 MiB
  that could have bought picture. It is remuxed out at ingestion — `-c copy`,
  once, the picture bit for bit what it was.

### The security pass, and what it actually found

Run on 2026-08-30 over a Semgrep export, a Semgrep autofix PR and 24 CodeQL
alerts. **Nine were real and every one of them was CI configuration**; the
rest were read against the code and dismissed with a reason.

- #161 — `inputs.tag || github.ref_name` was expanded inside a `run:` body in
  `release.yml`, so a crafted tag was shell source. Moved into `env:`. Line 60
  was the only such expansion in any of these workflows.
- #162 — `codeql.yml` was the one workflow not pinning its actions, and the one
  holding `security-events: write`. Pinned, with the SHAs resolved against the
  API; the codeql action's tag is annotated, so its ref endpoint does not answer
  the commit. Dependabot also gained a cooldown, which is a supply-chain measure
  here and a `main`-stays-green measure in practice.
- The `# v6` comments on six `uses:` lines named a release their SHA is not.
  That SHA is `v7.0.1`.

The 24 CodeQL alerts were false positives and are dismissed. If a future scan
raises them again, the reasons are in #162 rather than to be rediscovered: a
nonce buffer whose next line fills it from the CSPRNG, literal passwords inside
`#[cfg(test)]`, a `with_capacity` two lines under its bound, ten path joins each
behind a named guard — `secure_track_path`, `artwork_mime` before the join,
`clean_hash`, `clean_extension` — and eight logging alerts of which six print a
username and two print a one-time credential that is `println!` to stdout by
design, never `tracing`.

## Traps

**A document's header is not evidence about the code.** Every RFC here says
`Statut : Proposed`, including the two that had been in production for days. The
desktop agent read it, concluded three RFCs were unimplemented, and held three
of its own batches as blocked on a server that was ready. It had even noticed
`src/api/uploads.rs` and said aloud that RFC-008 "may be partly implemented" —
then moved on. **A contradiction noticed and dropped costs more than one never
seen.** The fix was not to flip the statuses: a status word cannot be audited, a
pull request number can. Each RFC now names its PRs, and `CLAUDE.md` says the
routes in `src/lib.rs` and the dated files under `migrations-v2/` are the only
real account.

**Remove the fix and watch the test fall. Every time — and say so when it does
not.** Two this week did not, and both are written down rather than implied
covered:

- Removing the reference-count guard in the blob lifecycle changed nothing,
  because `track_canvas.canvas_hash` references `canvas(hash)` with no
  `ON DELETE` clause and SQLite refuses the delete while a link remains.
  Removing *both* fails. The two are belt and braces; the constraint is the one
  that currently speaks.
- Removing `-map_metadata -1` and `-fflags +bitexact` from the audio remux
  changed nothing either: one FFmpeg build muxing the same packets twice agrees
  with itself. What they defend against is the version string that differs
  between builds, which no test running against a single build can see.

**A comment that contradicts its function is worse than no comment.** The
probe's comment said an audio stream "is deliberately not inspected" for two
commits after the code began detecting and removing it. It survived because the
decision changed and the paragraph three lines above the change did not.

**`git checkout <path>` restores from the index, not from your intent.** Used to
drop a temporary debug print, it took the real assertion out with it — the
commit would have carried a message describing a fix that was not there. Read
the file back before committing, not just the diff you meant to make.

**A feature branch is not created by wanting one.** One commit landed on `main`
by forgetting `git checkout -b`. Nothing was pushed, so `git branch` then
`git reset --hard origin/main` fixed it — but the hard reset also discarded an
unrelated uncommitted change that had been sitting in the tree since before the
session.

**Startup validation constrains what a test can configure.** `validate_canvas`
refuses a per-canvas ceiling above the library quota, so a test cannot squeeze
the quota between the arriving size and the stored size to prove which one is
charged. Fill the room instead: a first canvas takes all but exactly the
remainder. And when the filler must be large, buy the bytes with *detail* rather
than *duration* — a flat colour compresses to about a kilobyte a second, and a
filler long enough to matter trips the duration ceiling first.

**Two adjacent knobs are not one knob.** `accepts_uploads` and `accepts_canvas`
answer different questions, and the RFC only found that out because it had
written down the condition under which its own answer would stop holding. A
decision that names what would falsify it is worth more than one that sounds
certain.
